SECURITY & TRUST

The guarantees

SEC / 001 — EXECUTION
Does YUKTI ever execute the code it writes?+
No. Code produced by the mentor is parsed for syntax only — it is never compiled, run, or executed anywhere in the pipeline. The decision to execute stays entirely in your hands.
SEC / 002 — LOCALITY
Where does my repository data go?+
Repository scans build a summary in the working directory at scan time. Sessions persist locally in SQLite. Your full source tree never leaves the machine serving YUKTI.
SEC / 003 — VERIFICATION
How do I know the output is actually checked?+
Code-producing modes pass their output through a local parser, and the verdict — status, count of blocks parsed, and any issues found — is returned on every code answer. No silent best-effort paths.
SEC / 004 — HANDSHAKE
What is the secure OTP handshake?+
A one-time code seals and locks a session to a single gateway ID before the first mentor turn. Sessions that already carry a sealed handshake are resumed without re-locking.
SEC / 005 — PROVENANCE
Are the telemetry numbers real?+
Yes. The Telemetry page renders live data straight from GET /stats — exactly what the mentor has actually done, with nothing fabricated.
PRODUCT

What the mentor can do

PRD / 001 — MODES
What can the five modes do?+
Explain, Find Errors, Generate, Optimize, and Repo Report — each a specialized lens over the same verified engine. See the full sheets on the Mentor Modes page.
PRD / 002 — CONTEXT
Does the mentor remember my conversation?+
Yes. Sessions hold the thread; long conversations are folded into a memory summary instead of evaporating. Context turns are reported on the response.
PRD / 003 — COST
Can I see how much a turn cost?+
Always. Every turn records tokens in/out, model, provider, latency, and estimated cost — surfaced in the client and in /stats.
PRD / 004 — MODELS
Which models and providers are used?+
Routing is provider-agnostic and configured through environment variables — you pick the default, code, and cost-sensitive models. No vendor lock-in.
API

Connecting to the grid

API / 001 — ENDPOINTS
What API endpoints exist?+
POST /mentor (chat + verify), GET /sessions, DELETE /sessions/{id}, GET /stats, and GET /health. Full reference on the Docs page.
API / 002 — AUTH
Do I need API keys to read telemetry?+
Read endpoints are served by the local backend without extra auth. Model keys are read from environment configuration on the server, never from the browser.
API / 003 — ERRORS
What happens when the model provider is down?+
The backend returns a 503 with a clear detail message, and the UI surfaces it as an actionable status — never as a silent empty answer.
